## 1. 目标与边界

### 1.1 产品定位

StreamPilot 是**可管控、可审计、可随时接管**的 AI 虚拟主播操作系统：把「评论接入 → 内容安全 → 大模型回复 → 语音合成 → 数字人渲染 → RTMP 推流」串成一条可观测的实时链路，并配套人设管理、场次调度、成本核算与人工接管控制台。

它交付的是**AI 主播操作员**，不是「无人直播挂机工具」：

- AI 承担高频互动、欢迎、答疑、节奏维持；
- 人负责开播决策、异常处置、合规复核与关键时刻接管；
- 系统对每一条对外内容留存生成与审核证据。

### 1.2 目标用户与典型场景

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| 品牌自播间运营 | 长时段店播、夜间时段补位 | 话术一致、合规可控、成本可算 |
| MCN / 直播服务商 | 多直播间、多人设统一管理 | 多租户、集中监控、快速切换 |
| 持证虚拟形象创作者 | 以自有形象做常态化直播 | 形象/声音授权链清晰、可追责 |

明确**不服务**的场景：多账号批量养号、跨平台自动搬运、无人值守的「睡觉挂机」直播。

### 1.3 产品目标（可度量）

| 编号 | 目标 | 度量口径 | 目标值 |
| --- | --- | --- | --- |
| G1 | 互动响应及时 | 评论进入网关 → 首帧音频播出 | p50 ≤ 2.0s，p95 ≤ 3.5s |
| G2 | 出画完整 | 评论进入网关 → 画面出现对应口型 | p95 ≤ 5.0s |
| G3 | 内容安全可控 | 人工抽检中的违规漏放率 | < 0.1% |
| G4 | 误伤可接受 | 正常评论被拦截/改写比例 | < 5% |
| G5 | 直播连续性 | 单场 4 小时内的非计划中断次数 | 0 次；断流恢复 ≤ 15s |
| G6 | 人工接管有效 | 控制台点击接管 → AI 停声停画 | ≤ 3s |
| G7 | 成本可见 | 每场直播的 LLM/TTS/渲染成本可归集 | 100% 归集，误差 < 5% |
| G8 | 可追溯 | 任一条对外回复可回放「输入-审核-生成-合成」全链路 | 100% 可回放，留存 ≥ 90 天 |

### 1.4 范围

**In scope（本期产品范围）**

1. 抖音直播间评论/弹幕接入（仅官方开放平台能力）。
2. 输入与输出双向内容安全（规则 + 云审核 + 模型兜底 + 熔断）。
3. 多人设对话编排：上下文记忆、优先级、节奏控制、话题引导、超时丢弃。
4. Qwen 生成 + CosyVoice 合成 + 数字人唇形/表情/动作 + 画面合成。
5. 云端 RTMP 推流与断流重连；本地 Windows 凭据桥（直播伴侣登录取流地址）。
6. Web 控制台：场次管理、实时监控、人工接管、话术干预、审核复核。
7. 多租户与多直播间管理、成本看板、直播复盘、审计日志。
8. 开源工程基线：文档、接口契约、CI、IaC、贡献指南、合规声明。

**Out of scope（明确不做）**

- 群控、模拟点击批量操作、非官方协议/抓包/逆向接入。
- 名人肖像、名人声音克隆、未授权 IP 形象。
- 自研基础大模型、自研 TTS/ASR 模型。
- 电商交易闭环（下单、支付、履约）、私域导流工具。
- 「零人工值守」的产品承诺与宣传口径。

### 1.5 产品原则

1. **合规优先于效果**：任何提效手段与平台规则冲突时，放弃手段。
2. **安全默认拒绝（fail-closed）**：审核服务不可用时不出声、不出画，走兜底话术。
3. **单写者**：一个直播间同一时刻只有一个发声者、一个推流者，避免状态竞争。
4. **可接管**：任何自动化环节都必须有对应的人工控制入口。
5. **可回放**：每个决策点留痕，能回答「这句话为什么被说出来」。
6. **云边分离**：云端做计算与编排；本地只做必须在本机完成的账号登录与凭据桥接。

### 2.3 关键时序：一条评论的完整旅程

```
观众评论
  │ ① 平台回调（含签名、msg_id、时间戳）
  ▼
Ingest GW ──② 验签/幂等(Redis SETNX)/限流──▶ 规范化事件
  │
  ▼
Safety(输入) ──③ 规则DFA → 云审核 → 模型兜底──▶ 放行 / 拦截 / 需改写
  │  拦截则记录审核事件，不进入发言队列
  ▼
Orchestrator ──④ 去重、聚合窗口(300~800ms)、优先级排序、冷却检查
  │
  ├─▶ Memory ──⑤ 取短期上下文 + 长期摘要 + 观众标签
  │
  ▼
LLM Gateway ──⑥ 组装提示词 → Qwen 流式 ──▶ 句级切分
  │
  ▼
Safety(输出) ──⑦ 逐句审核；不通过则丢弃该句并触发改写或兜底
  │
  ▼
TTS Gateway ──⑧ CosyVoice 流式合成（命中缓存则直接取）──▶ 音频块 + 时间戳
  │
  ▼
Avatar Renderer ──⑨ 唇形/表情驱动 + 画面合成（含 AIGC 标识、字幕）
  │
  ▼
Streamer ──⑩ 抖动缓冲 → RTMP 推流 ──▶ 平台
  │
  └─▶ 全链路 span/trace + 成本记账 + 对话日志落库
```

### 2.4 通信与数据流

- **同步调用**：控制台 ↔ 各服务（REST，超时 3s）。
- **异步事件**：Redis Streams 作为轻量事件总线，主题见 [API.md](API.md#4-内部事件总线)。
- **状态存储**：Redis 存会话热状态与队列；MySQL 存配置、日志、审计、账单；OSS 存媒体。
- **事件顺序**：同一场直播内按 `session_id` 分区，消费者单并发，保证顺序。

### 2.5 失败与降级设计

| 故障 | 检测 | 处置 | 用户感知 |
| --- | --- | --- | --- |
| 审核服务超时/不可用 | 超时 300ms、错误率阈值 | fail-closed：暂停 AI 发言，切兜底话术，告警 | 短暂静默/安全话术 |
| LLM 超时/限流 | 首 token 超时 2s | 降级 qwen-turbo → 预设话术 → 跳过该条 | 回复变短或跳过 |
| TTS 失败 | 首包超时 1s | 重试 1 次 → 纯字幕模式（静音出字） | 无声但有字幕 |
| 渲染崩溃 | 心跳丢失 2s | 切备用渲染进程/静态形象 + 告警 | 画面短暂静止 |
| 推流断开 | RTMP 状态/帧率 | 指数退避重连（1s/2s/4s/8s，上限 15s） | 短暂中断后恢复 |
| 平台评论推送中断 | 60s 无事件 | 主动探测 + 告警 + 切「等待互动」话术 | 互动减少 |
| 本地凭据桥离线 | 心跳 10s | 保留当前推流，禁止新开播，告警 | 不影响在播场次 |
| 敏感事件熔断 | 规则命中高危 | 立即停声停画，进入人工接管 | 直播暂停 |

## 3. 技术选型及理由

### 3.1 选型原则

1. 主链路托管优先：LLM/TTS/ASR 用成熟托管 API，不自建推理集群。
2. 实时链路少跳数：能进程内合并的不跨服务，能流式的不等全量。
3. 运维成本可控：单一直播间用 Docker Compose 即可跑通，规模化再上 K8s。
4. 可替换：所有外部能力经 Gateway 封装，保留切换供应商的接口边界。
5. 合规可证：审核、标识、授权、接管均有落库证据。

### 3.2 选型表

| 领域 | 选择 | 备选 | 选择理由 | 不选备选的原因 |
| --- | --- | --- | --- | --- |
| 服务端语言 | Python 3.12 + FastAPI + Pydantic v2 | Node.js/TypeScript、Go | AI SDK 生态最完整；异步 IO 适合流式链路；团队上手快 | Go 的 AI SDK 生态弱；Node 在音频/媒体处理上弱于 Python |
| 实时通信 | HTTP + WebSocket（控制台）+ Redis Streams | gRPC、Kafka、RocketMQ | 降低运维面；Redis 已在架构中；Streams 支持消费组与回溯 | Kafka 对单间规模过重；gRPC 调试成本高 |
| 消息队列 | Redis Streams | RabbitMQ、RocketMQ | 与状态存储复用，延迟低，足够支撑单间 QPS | 独立 MQ 增加组件与成本，当前规模不必要 |
| 关系库 | MySQL 8（RDS） | PostgreSQL | 团队熟悉、托管成熟、成本低 | PG 能力更强但迁移与运维收益不明显 |
| 缓存/状态 | Redis 7 | Memcached | 需要 Streams、ZSET 优先级队列、TTL、Lua | Memcached 无持久化与数据结构 |
| 对象存储 | 阿里云 OSS | NAS、自建 MinIO | 媒体成本低、CDN 友好、生命周期策略成熟 | 自建增加运维与带宽风险 |
| LLM | 百炼 Qwen（qwen-plus 主 / qwen-turbo 快 / qwen-max 难） | 其他云厂商模型、开源自建 | 与 TTS/审核同云，网络与计费统一；中文直播话术表现好 | 跨云增加延迟与合规沟通成本 |
| TTS | CosyVoice（百炼） | 其他云 TTS、开源 TTS | 支持流式与授权音色克隆，中文自然度高 | 自建 TTS 的稳定性与音质维护成本高 |
| ASR | Fun-ASR（百炼） | Whisper 自建 | 仅用于语音互动/复盘等非主链路，托管更省事 | 主链路不需要 ASR，自建无收益 |
| 内容安全 | 阿里云内容安全 + 本地 DFA 词库 + 模型分类兜底 | 纯自建词库、纯云审核 | 三层互补：低延迟规则、广覆盖云审核、语义兜底 | 单层都有漏放/误杀短板 |
| 数字人渲染 | 2D 视频驱动/Live2D 为主，3D 作为高保真实体可选项 | 全 3D、纯静态图 | 2D 成本低、风格可控、唇形驱动成熟；3D 算力贵 | 全 3D 对单间投产比低 |
| 媒体管线 | FFmpeg + GStreamer | 纯 FFmpeg、OBS 脚本化 | GStreamer 适合低延迟管线与动态叠加；FFmpeg 做转码与兜底 | 纯 FFmpeg 难以做实时叠加与低延迟调度 |
| 前端 | React + TypeScript + Vite + Tailwind | Vue、Next.js | 控制台是 SPA，Vite 启动快；生态成熟 | Next.js 的 SSR 对内部控制台无收益 |
| 容器编排 | Docker Compose（单间）→ ACK（多间） | 直接上 K8s | 先压低复杂度，规模化再演进 | 早期 K8s 运维成本高于业务价值 |
| IaC | Terraform | 手动控制台、ROS | 可评审、可回滚、可复现 | 手动操作不可审计 |
| CI/CD | GitHub Actions | Jenkins、云效 | 开源仓库原生集成，零额外运维 | 自建 CI 维护成本高 |
| 可观测 | OpenTelemetry + Prometheus + Grafana + 阿里云 SLS | 纯自建 ELK | 指标/日志/追踪统一语义，云上托管省运维 | ELK 存储成本与运维成本高 |
| 密钥管理 | 环境变量注入 + 阿里云 KMS（生产） | 明文配置文件 | 满足「密钥不入库」硬约束 | 明文配置有泄露风险 |

### 3.3 关键取舍

- **不做端到端自研**：模型能力用托管，工程价值集中在编排、安全、可观测与运营。
- **不做多平台抽象**：本期只接抖音官方开放平台，避免过早抽象出错误的通用层。
- **本地与云分工**：本地只做无法上云的账号登录与凭据桥，降低本地环境成为单点故障的概率。
- **流式优先**：LLM 与 TTS 全链路流式 + 句级切分，用「早出声」替代「等全文」。
- **安全双通道**：规则在前（快），云审核并行（广），模型兜底（准），任一不通过即不出声。

## 6. 实时链路与延迟预算

### 6.1 端到端预算（单条评论）

| 阶段 | p50 | p95 | 优化手段 |
| --- | --- | --- | --- |
| ① 平台回调 → 网关接收 | 60ms | 150ms | 就近地域、连接复用、避免同步落库 |
| ② 验签 + 幂等 + 规范化 | 15ms | 40ms | Redis SETNX、无阻塞日志 |
| ③ 输入审核 | 120ms | 300ms | 规则前置（<5ms）、云审核并行、超时 300ms fail-closed |
| ④ 聚合/排队/冷却 | 300ms | 800ms | 窗口可配；高优评论插队；冷启动预热 |
| ⑤ 上下文构建 | 20ms | 50ms | Redis 读热态、摘要异步更新 |
| ⑥ LLM 首 token | 450ms | 900ms | 流式、短提示词、qwen-plus / 快路径 qwen-turbo |
| ⑦ 首句输出 + 输出审核 | 150ms | 350ms | 句级切分、审核与合成并行 |
| ⑧ TTS 首包 | 250ms | 500ms | 流式合成、热门话术缓存 |
| ⑨ 渲染首帧 | 80ms | 200ms | 常驻渲染进程、预加载形象、GPU 加速 |
| ⑩ 抖动缓冲 + 推流 | 300ms | 600ms | 缓冲 300~600ms、GOP 1s、码率自适应 |
| **合计（到首帧音频）** | **≈1.7s** | **≈3.4s** | 目标 G1 达标 |

> 测量点：①以网关接收时间戳为准，平台侧时间仅用于监控平台延迟；⑩以推流器写出首帧音视频的时间为准。完整计算与压测方法见 [ARCHITECTURE.md](ARCHITECTURE.md#延迟预算)。

### 6.2 背压与限流

- 单场待发声队列上限 20 条，超出按优先级丢弃（低优评论直接丢弃并记录）。
- 每条回复有效期 20s，超时未开播则丢弃，避免「答非所问」。
- LLM 并发按租户配额限制；TTS 并发按音色限制；渲染按场次独占。
- 平台回调限流：按 `room_id` + 窗口计数，超出返回 429 并记录（不丢队列中的事件）。

### 6.3 可观测指标（SLO）

| 指标 | 类型 | 目标 |
| --- | --- | --- |
| `reply_first_audio_latency` | Histogram | p95 ≤ 3.5s |
| `reply_end_to_end_latency` | Histogram | p95 ≤ 5s |
| `safety_block_rate` | Gauge | 监控异常突增（>20% 告警） |
| `safety_error_rate` | Gauge | < 0.5%，超阈值自动熔断 |
| `stream_reconnect_total` | Counter | 单场 0 次为健康 |
| `takeover_latency` | Histogram | p95 ≤ 3s |
| `tts_cache_hit_rate` | Gauge | ≥ 30% |
| `cost_per_hour` | Gauge | 按 [COST.md](COST.md) 预算告警 |

### 7.1 生产（阿里云）

| 层 | 资源 | 规格（起步） | 说明 |

### 7.2 本地 Windows 节点

- 运行抖音直播伴侣，由运营**人工登录**；
- Local Bridge 只做三件事：安全上报推流地址、心跳、一键停播；
- 不存储观众数据、不参与内容生成、不持有云上数据库凭据；
- 与云端用 mTLS + 短期令牌通信，令牌 15 分钟轮换。

### 7.3 环境分层

| 环境 | 用途 | 数据 | 外部能力 |
| --- | --- | --- | --- |
| dev | 本地开发 | 合成数据 | 可 mock，必要时用测试额度 |
| staging | 联调与压测 | 脱敏样本 | 真实 API，独立配额 |
| prod | 正式直播 | 真实数据 | 真实 API，独立密钥 |

### 7.4 发布与回滚

- 灰度以「单直播间」为单位，先影子模式（只生成不推流），再小流量。
- 配置（提示词、词库、阈值）与代码分离，配置变更同样走审批与版本记录。
- 回滚目标：代码 ≤ 5 分钟；配置 ≤ 1 分钟；人设版本即时切换。

## 8. 里程碑与验收标准

> 里程碑为**顺序门槛**，每阶段未通过验收不进入下一阶段。不预设日期，排期由团队规模与平台资质审批决定。

### M0 合规与资质就绪

**交付物**：开放平台能力申请材料、虚拟形象与音色授权台账、AIGC 标识方案、第三方推流合规结论、数据处理与隐私说明草案。

**验收**：
- 已书面确认可用的评论接入能力与调用配额；
- 形象与音色均有可追溯的书面授权，且未使用名人要素；
- AIGC 标识在画面与音频两个维度都有可执行方案；
- 对「云端推流是否被平台允许」给出明确结论；若不允许，切换到架构 B（本地伴侣推流）并更新计划。

### M1 工程底座

**交付物**：仓库规范、CI、环境分层、IaC、密钥管理、观测基线、契约包。

**验收**：
- 空脚手架可一键在 staging 起停；
- CI 覆盖 lint/类型/单测/密钥扫描，主干全绿；
- 任意服务故障能在 Grafana 看到指标与告警；
- 仓库中不存在任何真实密钥（含历史提交）。

### M2 接入与安全闭环（不对外）

**交付物**：事件网关、签名校验、幂等去重、三层审核、熔断、审核审计台、回放工具。

**验收**：
- 用录制的事件流回放 1 万条评论，幂等与顺序正确率 100%；
- 红队测试集漏放率 < 0.1%，误杀率 < 5%；
- 审核服务故障时 1s 内进入 fail-closed，不产生任何未经审核的对外文本；
- 每条评论可查到完整审核轨迹。

### M3 对话内核

**交付物**：编排状态机、优先级队列、人设版本管理、Qwen 接入、记忆与摘要、回复策略、离线评测集。

**验收**：
- 单场 4 小时模拟流量下队列不失控、无重复发言、无跨观众串话；
- 离线评测集上人设一致性、相关性、合规性均达标（阈值见评测规范）；
- 断网/超时/限流三类故障均可降级且不中断直播；
- token 成本可按场次归集。

### M4 语音与数字人

**交付物**：CosyVoice 流式接入、文本规范化、音频缓存、唇形驱动、表情/动作状态机、画面合成与叠加层。

**验收**：
- 首帧音频 p95 ≤ 3.5s，出画 p95 ≤ 5s；
- 音画同步偏差 ≤ 80ms；
- 数字人待机、说话、表情切换自然，无穿模/黑帧；
- AIGC 标识在画面中持续可见（符合平台与法规要求）；
- 音频缓存命中率 ≥ 30%。

### M5 推流与接管

**交付物**：本地凭据桥、云端推流器、断流重连、场景切换、控制台接管、场次状态机。

**验收**：
- 连续 8 小时推流无主动中断；人为断网后 ≤ 15s 恢复；
- 接管生效 p95 ≤ 3s，接管期间 AI 完全静默；
- 一键停播可同时停止音频、画面与推流；
- 推流凭据不出现在日志、数据库明文字段与前端。

### M6 灰度运营（单间）

**交付物**：影子模式、单间灰度、监控看板、事故演练报告、运营 SOP。

**验收**：
- 影子模式与真播对比，回复采纳率 ≥ 80%；
- 单间连续 5 场无 P0/P1 事故；
- 完成断流、审核不可用、模型限流、误熔断四类演练；
- 成本与预算偏差 < 15%。

### M7 产品化与多间扩展

**交付物**：多租户、多人设、多直播间调度、复盘报告、成本看板、开源治理文件。

**验收**：
- 3 个直播间并行运行，资源隔离与配额生效；
- 单间故障不影响其他场次；
- 复盘报告可自动生成并包含互动质量与合规指标；
- 新租户接入可在 1 小时内完成（含资质校验）。

## 9. 风险与合规清单

### 9.1 硬约束（不可协商）

1. AI 生成内容必须**显著标识**：画面持续角标 + 音频/简介声明，不得以任何方式弱化或隐藏。
2. 虚拟形象与音色必须**有书面授权**，禁止仿冒名人、禁止未授权 IP。
3. 评论接入**只走官方开放平台**，禁止抓包、逆向、群控、模拟点击、非官方协议。
4. 必须具备**人工接管**、**断流重连**、**敏感词熔断**三项能力。
5. 对外宣传**不得声称零人工值守**，运营文档必须写明人工监看要求。
6. 密钥、账号、密码、推流地址**不得**进入仓库、日志明文与前端包。

### 9.2 风险登记册

| ID | 风险 | 影响 | 概率 | 缓解措施 | 触发阶段 |
| --- | --- | --- | --- | --- | --- |
| R-01 | 平台不允许第三方推流 | 架构需调整 | 中 | M0 书面确认；准备架构 B：本地伴侣推流 + 画面回传/虚拟摄像头 | M0 |
| R-02 | 评论开放能力审批不通过或配额不足 | 主链路不可用 | 中 | 提前申请；准备降级为「人工录入演示模式」的内部验证路径 | M0 |

## 10. 成本估算

> 所有单价为**估算区间**，采购前必须以阿里云官网当期价格复核。以下按「单直播间、每天 4 小时、每月 30 天」建模。

### 10.1 流量假设

| 参数 | 假设值 | 说明 |
| --- | --- | --- |
| 月直播时长 | 120 小时 | 4h × 30d |
| 触发回复的评论 | 100 条/小时 | 经聚合后实际发声更低 |
| 月回复条数 | 12,000 条 | 100 × 120 |
| 单条输入 token | 800 | 含人设、上下文、观众标签 |
| 单条输出 token | 200 | 两句以内 |
| 单条 TTS 字符 | 120 | 中文按字计费 |
| 渲染 | 120 小时 | 与直播时长一致 |

### 10.2 月成本档位（估算）

| 项目 | 轻量档（CPU 渲染、2D） | 标准档（GPU 渲染、高保真 2D） | 高保真档（3D/多机位） |
| --- | --- | --- | --- |
| LLM（Qwen） | ¥30 ~ ¥120 | ¥120 ~ ¥400 | ¥400 ~ ¥1,200 |
| TTS（CosyVoice） | ¥300 ~ ¥600 | ¥400 ~ ¥800 | ¥600 ~ ¥1,200 |
| 内容安全 | ¥30 ~ ¥100 | ¥60 ~ ¥150 | ¥100 ~ ¥300 |
| 编排 ECS | ¥150 ~ ¥300 | ¥300 ~ ¥600 | ¥600 ~ ¥1,200 |
| 渲染算力 | ¥0 ~ ¥300（CPU） | ¥800 ~ ¥1,800（GPU 按量/包月） | ¥2,000 ~ ¥5,000 |
| RDS + Redis | ¥250 ~ ¥500 | ¥400 ~ ¥800 | ¥800 ~ ¥1,500 |
| OSS + 流量 | ¥50 ~ ¥150 | ¥100 ~ ¥300 | ¥200 ~ ¥600 |
| 监控/日志/带宽 | ¥100 ~ ¥250 | ¥200 ~ ¥400 | ¥400 ~ ¥800 |
| **合计（估）** | **¥900 ~ ¥2,300** | **¥2,400 ~ ¥5,200** | **¥5,100 ~ ¥11,800** |

### 10.3 成本控制

- TTS：常用话术缓存、句级复用、按音色限额；缓存命中率目标 ≥ 30%。
- LLM：短上下文、快慢模型分流、按租户配额、温度与 max_tokens 上限。
- 渲染：非直播时段停机；CPU 可满足时不上 GPU；按场次独占避免空转。
- 存储：OSS 生命周期（7/30/90 天分层），录像按需归档。
- 告警：按场次与按日双阈值，超预算自动降级到「字幕模式」。

完整计算表、单价来源与扩展公式见 [COST.md](COST.md)。
