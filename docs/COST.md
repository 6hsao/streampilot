# StreamPilot 成本估算

> 所有单价为**估算区间**，不构成报价。采购前必须以阿里云/百炼官网当期价格与计费规则复核。
> 建模口径：单直播间、每天 4 小时、每月 30 天（120 小时）。

## 1. 用量假设

| 参数 | 假设 | 说明 |
| --- | --- | --- |
| 月直播时长 | 120h | 4h × 30d |
| 评论量 | 100 条/h 触发回复 | 聚合后实际发声更少 |
| 月回复条数 | 12,000 | 100 × 120 |
| 单条输入 token | 800 | 人设 + 上下文 + 观众标签 |
| 单条输出 token | 200 | 两句以内 |
| 单条 TTS 字符 | 120 | 中文按字计费 |
| 输出审核次数 | 24,000 | 按每回复 2 句计 |
| 渲染时长 | 120h | 与直播同步 |

### 档位说明

- **轻量档**：Live2D 720p + CPU 软渲染，仅用于开发、联调与低频验证，不作为生产容量依据。
- **标准档**：Live2D 1080p30 + 单 GPU（T4/A10 级），首发生产默认档位。
- **高画质档**：双机位、60fps 或更高码率，面向品牌活动等短期场景。

## 4. 敏感性分析

| 变量 | 变化 | 月成本影响（标准档） |
| --- | --- | --- |
| 回复量翻倍 | 12k → 24k | TTS +¥400~800，LLM +¥120~400 |
| 直播时长翻倍 | 120h → 240h | 渲染 +¥800~1800，TTS/LLM 同比 |
| 上下文长度翻倍 | 800 → 1600 token | LLM +约 40%~80% |
| TTS 缓存命中 50% | — | TTS -¥150~300 |
| 渲染改包月 | 120h → 包月 | 视使用率，可能 -20%~-40% |
| 多直播间 | +1 间 | 约 +60%~+80%（共享 DB/监控；Post-1.0 才考虑） |

**结论**：TTS 与渲染算力是成本主项；优先优化这两项，LLM 单价虽低但上下文长度会放大。

## 5. 成本控制手段

### 5.1 TTS

- 欢迎语、FAQ、固定话术走音频缓存，目标命中率 ≥ 30%。
- 句级复用：相同文本 + 相同音色直接命中。
- 限制单条回复字符数（建议 ≤ 80 字），超长自动截断或分段。
- 按音色设置并发与字符配额，防止异常刷量。

### 5.2 LLM

- 快慢模型分流：简单互动用 qwen-turbo，复杂问答用 qwen-plus/max。
- 上下文裁剪：最近 6 轮 + 摘要，禁止全量拼接。
- 按租户/场次设置 token 预算，超限降级为模板话术。
- 提示词精简：人设与规则结构化，避免每次重复长文本。

### 5.3 渲染与推流

- 非直播时段停机，按场次启停。
- Live2D 固定 1080p30，不做无意义的高帧率；网络或平台受限时降 720p。
- GPU 按量优先，稳定后再评估包月；渲染节点与业务节点分离，避免相互抢占导致加机器。

### 5.4 存储与日志

- OSS 生命周期：7 天（音频缓存）→ 30 天（录像）→ 归档。
- 日志分级：INFO 30 天，ERROR 90 天，审计 1 年冷存。
- 关闭不必要的全量请求体日志，避免存储与脱敏成本。

## 6. 计量与告警

| 指标 | 采集方式 | 告警阈值 |
| --- | --- | --- |
| 每小时 LLM token | Gateway 记账 → `cost_ledger` | 超预算 120% |
| 每小时 TTS 字符 | TTS Gateway 记账 | 超预算 120% |
| 每小时渲染分钟 | Renderer 心跳 | 超预算 120% |
| 每场总成本 | 场次汇总 | 超单场预算 |
| 日成本 | 日汇总 | 超日预算 |

超预算动作：先告警 → 降低回复频率 → 切字幕模式 → 必要时停播（需人工确认）。
