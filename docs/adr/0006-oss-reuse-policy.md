# 0006. 开源复用与许可证门禁策略

- 状态：Accepted
- 日期：2026-11-15
- 决策人：技术负责人

## 背景

直播链路涉及弹幕、对话、TTS、Live2D、媒体推流与内容安全。全部自研不现实，但随意引入开源组件会带来许可证传染、供应链与合规风险。项目以 MIT 发布，必须保证发布物与上游许可兼容。

## 决策

1. **先调研再实现**：每个模块先评估成熟开源方案，记录能力边界与许可证（见 [OPEN-SOURCE.md](../OPEN-SOURCE.md)）。
2. **默认拒绝** GPL/AGPL、无许可证、自定义附加条件许可；确需使用须法务评审并隔离。
3. **LGPL 组件**（FFmpeg/GStreamer）以独立进程或动态链接使用，提供声明与可替换性说明。
4. **专有运行时与资产**（Cubism Core、Live2D 模型、音色）不入库，按官方/合同授权部署。
5. **准入流程**：SPDX 核对 → 兼容性判定 → NOTICE/声明 → 漏洞扫描 → 版本固定 → 记录退出成本。
6. **CI 门禁**：`INF-08` 生成 SBOM 并扫描许可证，违规直接阻断合并。

## 备选方案

| 方案 | 优点 | 不采用原因 |
| --- | --- | --- |
| 全部自研 | 许可最干净 | 周期与质量不可接受 |
| 直接 fork 完整项目 | 上手快 | 现有项目多为 GPL/附加许可，且与本项目合规链路不匹配 |
| 逐模块复用 + 门禁 | 平衡速度与风险 | 需要额外维护组件清单 |

## 影响

- 正面：许可风险前置；复用决策可追溯；发布物可举证。
- 负面：引入组件需评审与归档，短期增加流程成本。
- 跟随改动：`INF-08`、`LIV-09`、`SAF-01`、`AVT-04`、根目录 NOTICE/组件清单。
