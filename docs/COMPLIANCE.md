# StreamPilot 合规与内容安全

> 本文是产品硬约束的执行说明，不是法律意见。上线前应由具备资质的法务/合规人员复核。
> 相关：[PLAN.md](PLAN.md#9-风险与合规清单) · [API.md](API.md#5-安全生成与语音内部)

## 1. 适用规则（名称层面）

| 类别 | 规则 | 对本项目的主要要求 |

| 个人信息 | 《中华人民共和国个人信息保护法》 | 告知同意、最小必要、去标识化、删除权 |
| 深度合成 | 《互联网信息服务深度合成管理规定》 | 显著标识、不得用于非法目的、不得侵害他人权益 |
| 生成式 AI | 《生成式人工智能服务管理暂行办法》 | 内容安全、训练与生成合规、投诉与处置机制 |

| 直播营销 | 《网络直播营销管理办法（试行）》 | 主体资质、内容审核、消费者权益 |
| 广告 | 《中华人民共和国广告法》 | 禁用绝对化用语、虚假宣传、特殊品类限制 |
| 平台规则 | 抖音开放平台与直播规则 | 仅用官方能力、账号资质、内容与推流限制 |

> 具体条款编号与最新修订以官方发布为准；平台规则变化频繁，按季度复审。

## 2. 六条硬约束

1. **显著标识**：AI 生成内容在画面与音频/简介两个维度同时标识，且不能被遮挡、缩小到不可读或随场景移除。
2. **授权链完整**：虚拟形象、音色、背景素材均有书面授权；禁止名人肖像、名人声音、未授权 IP。
3. **官方接入**：评论/弹幕只通过平台官方开放能力获取；禁止抓包、逆向、群控、模拟点击、非官方协议。
4. **三项兜底**：人工接管、断流重连、敏感词熔断必须可用且经过演练。
5. **不宣称零人工**：所有对外材料与销售话术不得出现「无人值守」「零人工」等表述。
6. **密钥零泄露**：API Key、token、密码、推流地址不得进入仓库、前端包、日志明文。
7. **云端推流合规**：必须取得平台书面许可或明确规则依据；推流地址与 key 只允许内存与 KMS 密文引用，禁止明文落库与转交第三方。
8. **Live2D 授权**：遵守 Cubism SDK 许可与营收阈值判定；模型、动作、贴图必须有商用授权，专有运行时与资产不得入库。

## 3. 审核策略

### 3.1 三层审核

| 层 | 手段 | 延迟量级 | 覆盖 | 失败策略 |
| --- | --- | --- | --- | --- |
| L1 规则 | DFA 词库、正则、白名单、话题黑名单 | < 5ms | 明确违规词、联系方式、导流、辱骂 | 命中高危直接拦截 |
| L2 云审核 | 阿里云内容安全（文本为主，图片按需） | 100~300ms | 政治、色情、暴恐、违禁、辱骂、广告法 | 超时 fail-closed |
| L3 模型兜底 | 轻量分类提示词或小模型 | 100~400ms | 擦边、诱导、隐喻、越狱 | 不确定则拦截或改写 |

**输入侧**：拦截的评论不进入发言队列，仅记录审核事件。
**输出侧**：逐句审核；单句不通过则丢弃该句，允许一次安全改写；改写仍不通过则整条丢弃并计入指标。

### 3.2 分级处置

| 级别 | 示例 | 处置 |
| --- | --- | --- |
| 高危 | 政治敏感、违禁品、色情、暴力 | 拦截 + 记录 + 必要时熔断 |
| 中危 | 辱骂、地域歧视、诱导消费 | 拦截或改写 + 冷却 |
| 低危 | 联系方式、外部导流、绝对化用语 | 改写或忽略 |
| 安全 | 正常互动 | 放行 |

### 3.3 阈值与熔断

- 单场 5 分钟内拦截率 > 20%：告警并人工复核（可能是刷屏攻击或规则误伤）。
- 审核错误率 > 1%（2 分钟）：自动熔断，停止 AI 发声。
- 出现高危命中：立即静默，进入人工接管，保留证据。
- 恢复：默认人工确认；自动恢复仅在连续 5 分钟健康后允许，且需配置开启。

## 4. AIGC 标识实现要求

| 维度 | 要求 | 验收方式 |
| --- | --- | --- |
| 画面 | 持续角标，含「AI 生成」或等效表述，字号可读、对比度足够、不随场景切换消失 | 每 10 分钟抽帧，标识可见率 100% |
| 音频 | 开播口播声明 + 简介文字声明 | 录音抽检 + 简介截图 |
| 简介/标题 | 明确说明为 AI 虚拟主播 | 场次配置校验 |
| 素材 | 合成音频、生成文本留痕，可举证 | 日志与 OSS 归档 |

禁止：把标识做成不可读小字、仅在角落实时隐藏、用动画规避、仅在部分时段显示。

## 5. 授权管理

| 资产 | 必备材料 | 校验点 |
| --- | --- | --- |
| 虚拟形象 | 著作权/肖像授权书、授权范围、期限 | 上播前校验 `authorization_expires_at` |
| Live2D 模型 | 美术制作合同、拆分/绑定/动作授权、可否商用与转售 | 上播前校验模型授权与 `manifest` 版本 |
| Live2D 软件 | Cubism SDK Release License（最近财年营收 ≥ 1000 万日元时必须取得） | 上线前由法务确认并归档 |
| 音色 | 声音权利人授权、使用范围、期限 | TTS 调用前校验 |
| 背景/音乐 | 商用授权或自有版权 | 素材入库时校验 |
| 平台账号 | 主体资质、直播权限 | 开播前校验 |

到期前 30 天提醒；过期资产自动禁用，禁止「先播后补」。

## 6. 数据合规

- **最小必要**：只采集互动所需的评论内容与必要标识；不采集与直播无关的个人信息。
- **去标识化**：观众 ID 单向哈希后存储；展示昵称按平台规则处理。
- **留存**：评论 30 天、回复 90 天、审计 1 年（详见 [DATA-MODEL.md](DATA-MODEL.md#4-留存与删除)）。
- **访问**：最小权限 + 审批 + 审计；导出需二次确认。
- **删除**：支持按主体删除；删除请求有工单与时限。
- **跨境**：默认不跨境传输；如使用境外服务（如 Azure 实验环境）不得涉及真实用户数据。

## 7. 运营要求

1. 每场直播必须有**人工监看**，明确责任人；无人监看不得开播。
2. 建立接管值班表与升级路径（运营 → 合规 → 负责人）。
3. 每场收播后做**合规抽检**：随机 20 条回复 + 全量高危事件。
4. 每周汇总拦截/误伤/接管数据，更新词库与提示词。
5. 对外宣传材料由合规审核后才可发布。

## 9. 事故分级与 SOP

| 级别 | 定义 | 响应 | 处置 |
| --- | --- | --- | --- |
| P0 | 违规内容对外播出、形象/声音侵权、密钥泄露 | 立即 | 停播 → 接管 → 取证 → 上报负责人与法务 → 复盘 |
| P1 | 审核服务不可用、持续断流、大规模误杀 | 5 分钟内 | 熔断/降级 → 人工接管 → 修复 → 复盘 |
| P2 | 短时延迟升高、单条误判、画质下降 | 30 分钟内 | 观察/调整配置 → 记录 |

**P0 处置顺序**：停止输出 > 保留证据 > 通知责任人 > 评估影响 > 修复 > 复盘 > 更新规则。

## 10. 明确禁止的做法

- 抓包、逆向、模拟点击、群控、非官方协议接入评论或推流。
- 名人肖像/声音克隆、未授权虚拟形象、盗用他人直播素材。
- 隐藏或弱化 AI 标识、用「真人」话术误导观众。
- 绕过审核直接发声、审核故障时继续直播。
- 承诺「无人值守」「零人工」或替代主播全部职能。
- 将密钥、账号、推流地址写入代码、提交历史、日志或前端。
- 把推流地址/stream key 发送给第三方、粘贴到工单或群聊。
- 在未取得平台许可的情况下用第三方工具直推 RTMP，或规避平台推流限制。
